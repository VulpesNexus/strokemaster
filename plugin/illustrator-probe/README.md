# StrokeMaster Illustrator diagnostic probe

**PROPOSED — compile/link and mock tests only. Never loaded or verified in Illustrator.** This is an isolated native integration experiment, not the StrokeMaster stroker or a production plugin. The architecture evidence and remaining gates are in *docs/ILLUSTRATOR_ARCHITECTURE_AUDIT.md* at the repository root.

The native diagnostic command is registered as *Create diagnostic line* under the filter category *StrokeMaster PROPOSED*. Its actual menu placement and invocation are unverified. On explicit invocation with a current document, it creates one new 120 pt horizontal line at (100, 100)–(220, 100), applies an 8 pt solid gray stroke, and attaches the registered stroke replacement. It ignores selection and never opens, closes, saves, or exports a document. A failed attachment attempts to delete only that new line. Even successful cleanup does not promise unchanged dirty/undo state. Future invocation belongs in a disposable document.

The automation entry point is `app.sendScriptMessage` with the PiPL-verified plugin name `StrokeMasterProposedProbe`. Selector `status` takes empty input; selector `create` takes `control` or `effect`. Returned JSON has `schema: 1`, `status: "PROPOSED"`, the exact plugin name, `ok`, `error`, `goCalls`, `mutations`, `strokeOrigin`, `lastGoError`, `effectFixtures`, and `controlFixtures`. `mutations` counts successful Go replacements, not individual suite calls. Stroke origins are 0 missing, 1 transformed instance, 2 instance, and 3 parameters. Counters begin at zero in newly allocated plugin state and persist across binary reloads; no actual host counter value has been observed. The control has no effect and sits at y = 140. Status never edits art. No undocumented menu command is needed.

*host-proof.jsx* is an unexecuted Illustrator harness that creates and closes only its own disposable document, compares control/effect counters, and edits the effect source. It returns a checked structured record using a strict parser without `eval` or a global JSON dependency. It never saves or closes an existing user document. It tests plain-line dispatch only; render/output geometry and native stroke suppression still require inspection. Session-wide counters can include reevaluations of other documents. The Unicode adapter uses the acquired suite directly on borrowed message strings and carries no global suite pointer.

The effect callback accepts only an open, two-anchor, straight, unfilled processing path, optionally under at most four single-child groups. It requires a finite positive stroke width no greater than 1,000 pt, solid gray ink, no dash, and butt caps. Coordinates are bounded to ±1,000,000 pt, and segment length must be at least 0.001 pt. Text, compound paths, multiple children, clipping masks, fills, curves, non-gray colors, and unsupported styles return an error. The callback requires the stroke-style dictionary entry; it does not guess from the basic source style. It makes the processing leaf a filled rectangle and preserves the root handle. The editable source is not a mutation target.

The rectangle intentionally resembles an ordinary straight stroke. Seeing it alone cannot prove replacement: a future test must inspect callback traces and result geometry, confirm the source still has two anchors, and establish that only the generated filled rectangle supplies the stroke contribution. This first step tests dispatch and ownership, not miter clipping. No curved stroker, glyph extraction, Pathfinder operation, document observer, or polished UI is included.

*Probe.cpp* owns per-invocation suite references through guards. Entry conversion consumes the reference obtained from the dictionary; it must not be released twice. Parameter dictionaries created for attachment are released after dependent operations. Persistent state contains only host handles allocated through PICA, with no cached suite pointers or virtual tables. Startup/reload does not edit art. An output-mutation error triggers restoration of count, segments, closure, and paint on the same processing leaf. Persistent failures during restoration or fixture disposal remain explicit host-test concerns; the original error is returned and cleanup errors reach debugger diagnostics.

*build.ps1* requires PowerShell 7, an installed Python, VS2022/v143, and the external Adobe Illustrator 2026 SDK. Its required `SdkPath` argument points at that SDK; optional `Python`, `Toolset`, and `WindowsSdk` arguments select local dependencies. The tested defaults are MSVC 14.42.34433 and Windows SDK 10.0.26100.0. All generated inputs, PiPL, resources, objects, logs, tests, and binaries remain under this folder's ignored *build/* directory. The script normalizes duplicate environment-key casing only for its MSBuild child process and bounds each build to 60 seconds. It does not install or load the resulting *.aip*.

The project builds x64 only, uses eight-byte packing and C++17, and exports `PluginMain`. The supplied SDK has legacy Windows-1252 headers; the build explicitly uses that source character set with UTF-8 execution strings. The original probe/test sources are ASCII. SDK headers and the PiPL generator are read in place; no Adobe source implementation or headers are copied into this folder. Python runs with bytecode generation disabled. No redistributable package is created.

*ProbeTests.cpp* supplies mock suite functions in a separate executable. It checks Pascal filter string lengths/payloads before bounded reads, lifecycle/idempotent registration, failure of each Go suite acquisition, rollback at each of four mutation stages, nine unsupported-input/conversion cases, single-child wrapper output and exact rectangle sides, successful/failed fixture attachment cleanup, and the status/create/counter protocol. The Pascal regression failed on the original space-prefixed strings and passed after their replacement with bounded arrays. These tests verify the original C++ code against mocks, not Adobe's implementation. *build/compile.log*, *build/tests-compile.log*, and *build/tests.log* record the local checks. *verify_build.py* parses PiPL identity/entry-point fields, checks their exact embedding in the x64 DLL, and records the SHA-256 in *build/artifact.json*. Optional diagnostics use `OutputDebugStringA` with fixed status labels/error codes; they do not write document data or create a log file from Illustrator.

Independent review found and corrected the Pascal registration defect and confirmed entry conversion reference consumption. Final script-bridge review, actual loading, suite availability, stroke-style delivery, input ownership, unsupported-input error behavior, undo, source edits, output inspection, save/reopen, and export remain unverified. No restart or installation was performed for this delivery. Miter clipping, arbitrary Appearance, and opacity/transparency support remain unimplemented or unverified; the specimen is a plain solid line.
