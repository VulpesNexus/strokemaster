# Closed-region adapter scaffold

**MOCK_SCAFFOLD_ONLY — provisional core type binding, without real-kernel execution, Illustrator SDK output, or plugin integration.** *TopologyAdapter.h* is a host-independent conversion and transaction facade. *TopologyAdapterTests.cpp* tests it against a reference-output double and an independent analytic admission oracle. *test_topology_adapter.py* builds only the isolated test executable under *build/topology-adapter-tests/*, with warnings treated as errors; it checks the prep-4 frozen AIP hash before and after. It does not rebuild, install, or operate the plugin.

The approved first output is the full filled region for generated equal-gray fill/stroke art. This makes the union of fill and stroke the intended same-paint result. It is not a stroke-only band. The reserved separate identity is `org.strokemaster.proposed.closed-region.v1`; it is a string in the scaffold, not a registered effect. The two-point stroke replacement remains unchanged. Integration must wait for Euler's stable, independently reviewed reusable API and the protected-region/distant-envelope fixes.

The source describes one closed linear shell and zero or one explicitly labeled hole. Ring vertices omit a duplicate closing point. Source provenance must be diagnostic-generated; arbitrary existing artwork and unresolved winding are refused. Fill and stroke must both be present, equal gray, opaque, a single plain miter stroke, and free of brushes, dashes, overprint, and unsupported Appearance. Width, miter limit, coordinates, contour size, closure, finite values, and straight Bézier handles are checked. Host integration must establish these facts from actual SDK state; setting facade booleans is not host verification.

Conversion creates new value data and does not mutate input. Numeric ring checks are deliberately not advertised as polygon-topology validation. The future kernel binding must validate simple rings, hole containment, numeric budgets, and protected-region retention; a separate admission oracle must approve the output. No output sink call occurs before computation, output bounds, and admission pass. Multiple components and more than one output hole are outside this first scaffold.

The owned-output interface has three operations: stage, commit, and rollback. The future SDK implementation must record each newly created root/child handle before subsequent operations can fail. It receives no preexisting source handle. Ownership transfers only when commit returns success; false or throwing stage/commit triggers rollback, and rollback failure is reported distinctly. The mocks exercise partial-root failure, commit failure, exceptions, and explicit cleanup failure. These establish facade sequencing, not the safety of an unimplemented SDK compound-art backend.

## Independent analytic admission specimen

Use outer square [0, 10] × [0, 10] and triangular hole with vertices (0.2, 4), (2.2, 5), and (0.2, 6). The left outer wall starts only 0.2 pt thick. Use stroke width 0.2 pt, so outward buffer distance h = 0.1 pt, miter limit 4, and equal gray fill/stroke. The shifted-line oracle is independent of Boost or Adobe geometry.

The expected outer miter ring is the square [−0.1, 10.1]². Let q = h√5. The surviving hole vertices are (0.2 + h, 4 + (h + q)/2), (2.2 − q, 5), and (0.2 + h, 6 − (h + q)/2). Outer area is 104.04 pt²; hole area is (2 − h − q)²/2. The thin left wall becomes 0.4 pt. The acute hole tip contracts; it does not cross the expanded outer boundary.

The oracle checks vertices up to cyclic start and direction, with absolute coordinate tolerance 10⁻¹⁰ pt, while the independent scalar checks verify area and thin-wall thickness. Tests reject a lost hole, a hole crossing the outer edge, a 10⁻⁶ pt local shell perturbation, and nonfinite output before staging. The reference-output double intentionally returns the analytic result; its pass does not certify the real kernel. Euler's actual API output must pass this oracle before adapter admission. Additional tiny protected-feature tests and precision fixes remain kernel review gates.

## Pending API relay and native work

The current provisional binding includes root *tools/topology_region_core.h*. It maps to `ise::topology::Request::source` with a single `Polygon::outer` and explicitly labeled holes, `h`, `limit`, and `Join::Miter`. Every ring repeats its first vertex for the core and removes exactly that terminal closure on return. `CoreKernel` calls the supplied noexcept process function and preserves `Status` plus a bounded 512-byte message. Non-Ok results never reach staging; non-Ok results carrying geometry/comparisons/probes are additionally flagged as contract violations. Multi-component, excessive-hole, unclosed, or nonfinite output is refused. The default binding names the real process function, but current executable tests inject a mock with the same function type. This is not a competing stable ABI or real-kernel certification.

After the API passes the analytic fixture, investigate the SDK's compound-path construction and winding/paint contract for holes. Prefer materializing already validated rings directly over adding a second Boolean engine. An SDK Boolean operation is needed only if the actual host representation requires it; enum presence does not prove that requirement or functionality. Plan transactional owned-art output and inject each SDK failure before registering or testing the separate effect. Do not change *Probe.cpp* or the frozen binary before that review.

Current verification: 87 assertions pass with C++17, the plugin-compatible `/MD` runtime, and warnings treated as errors.
