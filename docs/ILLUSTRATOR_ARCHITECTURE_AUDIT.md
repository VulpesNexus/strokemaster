# Illustrator SDK architecture audit

Status: **SOURCE-ONLY VERIFIED; native implementation PROPOSED**. Reviewed 2026-09-12 against the locally supplied Adobe Illustrator 2026 SDK. Header contracts and sample control flow were inspected; Illustrator was not operated, and no load, callback, screen, export, undo, or persistence behavior was verified. A successful later compilation must remain labeled **PROPOSED, compile-only**. This document paraphrases findings and contains no proprietary excerpts. All SDK citations below are relative to the supplied SDK root, with one-based source lines; the SDK is an external build dependency and is not included in this repository.

The isolated native diagnostic is in *plugin/illustrator-probe/*. It implements a plain straight-line stroke replacement, not a full stroker or miter algorithm. It is not installed or host-tested yet. No SDK files were changed or redistributed.

## Ranked options A–G

The letters preserve the takeover prompt's option names. Ranking measures suitability for editable, constant-width stroke replacement, not maturity. Several options are complementary layers rather than competing complete implementations.

| Rank | Option | Finding and gate |
| --- | --- | --- |
| 1 | B. Stroke filter | A specialized Live Effect registered with `kStrokeFilter` replaces the stroke paint operation by contract. The parser explicitly exposes replacement paint effects and names brushes and aligned strokes as examples. Strongest fit for preserving separate fills and Appearance structure, but external callback dispatch, incoming geometry, style propagation, and live text are unverified. Gate: the native replacement proof below. Sources: *illustratorapi/illustrator/AILiveEffect.h*:232–248; *illustratorapi/illustrator/AIArtStyleParser.h*:516–541. |
| 2 | A. Live Effect | Automatic reevaluation on source edits is documented. Generic pre/post effects need deliberate placement relative to paint; a pre-effect that edits centerlines still leaves native stroking afterward. Input conversion is conditional, and the outlined-stroke input flag is explicitly unimplemented. Gate: inspect actual input at each placement and return controlled output. Source: *illustratorapi/illustrator/AILiveEffect.h*:242–245, 297–361, 679–707. |
| 3 | C. Art style manipulation | Required integration machinery for B or A: preserve unrelated fills, strokes, effects, and transparency while changing one stroke field. It does not itself provide a new join algorithm. Basic path style cannot represent every Appearance stack. Gate: deliberately different character, basic path, and multi-stroke Appearance settings survive attachment and round-trip. Sources: *illustratorapi/illustrator/AIArtStyle.h*:252–268, 292–297, 336–343; *illustratorapi/illustrator/AIArtStyleParser.h*:75–81, 110–120, 464–541. |
| 4 | D. Custom art generation | Necessary output mechanism for a custom silhouette. A plugin group can separate edit and result art and receive updates. Ordinary generated paths alone are static. Gate: topology, paint, clipping, ownership, and regeneration tests; do not mistake a raster union for vector region resolution. Sources: *illustratorapi/illustrator/AIArtStyle.h*:256–265; *illustratorapi/illustrator/AIPluginGroup.h*:89–107; *illustratorapi/illustrator/AIArt.h*:550–563. |
| 5 | F. Document observer + generated companion geometry | Plausible fallback retaining original text and separate generated art, but requires identity tracking, update filtering, deletion, transforms, undo, and recursion control. The inspected sources do not establish a complete observer implementation. A plugin-group update contract is stronger evidence than assuming a selection notifier catches every edit. Sources: *illustratorapi/illustrator/AIPluginGroup.h*:89–107; *illustratorapi/illustrator/AITextFrame.h*:339–347. |
| 6 | G. Native plugin command | Best bounded diagnostic and explicit static conversion harness. An ordinary filter command is not automatically live; it can attach B or A to obtain that behavior. Gate: explicit invocation, owned fixture creation, failure cleanup, and undo. Sources: *samplecode/TwirlFilter/Source/TwirlFilterPlugin.cpp*:178–208, 282–299; *samplecode/StrokeFilter/Source/StrokeFilterPlugin.cpp*:134–165, 229–246. |
| 7 | E. Appearance interception | If this means editing Appearance, use C. If it means a global paint interception/replacement callback, no such general contract was established in this audit. Do not infer an interception API from access to styled art. Gate: identify and test a specific public hook before implementation. Source: *illustratorapi/illustrator/AIArtStyle.h*:263–290. |

Recommended composition: G for the diagnostic command, C for explicit attachment, B for reevaluation and stroke replacement, and narrowly bounded D for output. Preserve the user's editable source. None of the seven options is certified for transforms, undo/redo, copy/paste, save/reopen, export, linked assets, or missing-plugin behavior by this source audit. The header documents an editing limitation when an applied effect is unavailable; this is not a tested compatibility result (*illustratorapi/illustrator/AILiveEffect.h*:690–691).

## Full TwirlFilter processing trace

1. Startup calls the common startup, then registers menus, ordinary filters, live effects, and notifiers. Post-startup constructs the processor. Live registration requests groups, paths, and compound paths with `kPostEffectFilter`; menu enablement requests paths. Sources: *samplecode/TwirlFilter/Source/TwirlFilterPlugin.cpp*:78–108, 213–249.
2. Common message dispatch maps the live caller and Go selector to `GoLiveEffect`; Twirl passes to the live overload of `GoTwirl`. The sample also has custom apply-notifier forwarding, which is separate from standard live-effect dispatch and is not needed for a minimal probe. Sources: *samplecode/common/source/Plugin.cpp*:357–365; *samplecode/TwirlFilter/Source/TwirlFilterPlugin.cpp*:123–130, 276–284.
3. Live parameter editing first queries selected paths/mystery paths, collects an angle, writes dictionary values, and calls `UpdateParameters`. This path-oriented selection requirement is not evidence that the sample's UI accepts arbitrary live text. Source: *samplecode/TwirlFilter/Source/TwirlFilter.cpp*:57–113, 179–225.
4. Live Go reads the angle from `parameters`; absence returns success without changes. It reads the supplied art's bounds/type, converts degrees to radians, and computes bounding-box center and half-diagonal. It calls `DoTwirl` on the supplied handle. Source: *samplecode/TwirlFilter/Source/TwirlFilter.cpp*:387–423.
5. `DoTwirl` walks the root's children, twirls path children, and recursively visits group children. For each path segment, the anchor's radial distance determines a rotation relative to the center. The same matrix transforms the anchor and its incoming/outgoing handles; segments are written back. No stroke expansion, custom join, or replacement output is produced. Source: *samplecode/TwirlFilter/Source/TwirlFilter.cpp*:351–385, 442–493.
6. Live Go adjusts local progress state, checks cancellation, and returns. Its local reassignment of `path` never assigns `pb->art`. Static defects: root paths are not dispatched; compound-path children are skipped; Go ignores `DoTwirl`'s error; progress increment can be uninitialized; sibling-read errors are not propagated. The sample does not establish robust arbitrary-art traversal. Source: *samplecode/TwirlFilter/Source/TwirlFilter.cpp*:351–439.
7. The ordinary filter overload follows a different route: query selected document paths, compute their union bounds, twirl each directly, update progress/check cancellation, and release the matching-art allocation on success or error. Source: *samplecode/TwirlFilter/Source/TwirlFilter.cpp*:235–349.

The sample named StrokeFilter registers ordinary `AIFilter` commands, then adjusts Beautiful Strokes dash/width settings. Its name and acquired Live Effect suite do not make it an example of third-party `kStrokeFilter` registration. Sources: *samplecode/StrokeFilter/Source/StrokeFilterPlugin.cpp*:134–165, 229–246; *samplecode/StrokeFilter/Source/StrokeFilters.cpp*:22–75.

## Ownership and suite gates

- `AILiveEffectGoMessage::art` is mutable processing input/output. Do not modify ancestors or the document artwork tree from Go. Delete removed input objects correctly; assigning null delegates input disposal to Illustrator. `srcArt` is a separate source reference, not permission to alter source geometry. Never use selection or a remembered document handle as Go's mutation target. Source: *illustratorapi/illustrator/AILiveEffect.h*:422–441.
- A handler that changes the returned root must assign `message.art`; an alias assignment is insufficient. Prefer an in-place, narrowly validated processing-art transformation for the first proof, with rollback on suite failure. Unsupported input should not be promoted to successful replacement. Host handling of returned errors remains a native test gate. Sources: *illustratorapi/illustrator/AILiveEffect.h*:297–301, 432–438; *samplecode/TwirlFilter/Source/TwirlFilter.cpp*:423–425.
- `GetStyledArt` exposes regenerated result art, not a persistent editable cache. Work through art styles outside Go; inside Go operate only on supplied processing art. Newly created effect paths can default to black fill/no stroke, so assign output paint deliberately. Sources: *illustratorapi/illustrator/AIArtStyle.h*:263–290; *illustratorapi/illustrator/AIArt.h*:550–563.
- Attachment workflow: retrieve the source style, allocate/parse a parser, check parseability, locate the intended stroke field, set its replacement effect, create a new style, apply it, and dispose the parser. A simpler merge call can replace the stroke in a deliberately simple diagnostic style. Replacing a brush/alignment effect can remove existing behavior; do not silently overwrite it in production. Sources: *illustratorapi/illustrator/AIArtStyleParser.h*:110–155, 173–210, 368, 516–541; *illustratorapi/illustrator/AIArtStyle.h*:336–343; *illustratorapi/illustrator/AILiveEffect.h*:855–865.
- Parser-created effect parameter dictionaries require `CreateLiveEffectParameters` for undo support. Balance the initial dictionary reference with `Release`. Parser-owned structures are disposed with the parser; do not double-dispose them. Source: *illustratorapi/illustrator/AILiveEffect.h*:877–890; *illustratorapi/illustrator/AIArtStyleParser.h*:591–613.
- Dictionary `Get` returns a reference-counted entry. The `AIEntrySuite` conversion functions consume the passed reference, so do not release it again after `ToStrokeStyle`. This differs from functions such as `GetType`, which do not consume the entry. Source: *illustratorapi/illustrator/AIEntry.h*:232–251, 517–523.
- Stroke replacement paint data can be provided through `kTransformedStrokeStyleKey` in instance info; prefer it when present, otherwise inspect `kStrokeStyleKey`. Test where that ordinary key is delivered rather than assuming a basic source path style is authoritative. Width, gradients, and style matrices are distinct concerns. Source: *illustratorapi/illustrator/AILiveEffect.h*:170–190.
- Acquire every required suite with its advertised version, check every acquisition, and release in reverse lifetime order after dependent work. No callback may retain an unowned suite pointer, transient input art, or borrowed dictionary beyond its lifetime. Keep parallel execution disabled until threading and suite availability are tested. Sources: *samplecode/TwirlFilter/Source/TwirlFilterSuites.cpp*:36–51; *illustratorapi/illustrator/AILiveEffect.h*:268–272, 718–728.

## Pathfinder and text boundaries

`AIPathfinderData` takes an explicit art array/count and exposes an output handle; `Init` initializes operation parameters. Unite, Intersect, and subtraction are geometry operations, not a clipping policy or proof of safe use inside Go. A filter-message argument with null fields is documented. Precision is in microns; even-odd handling and empty output require deliberate choices. Exercise output ownership, consumed operands, holes, degeneracies, and error cleanup before adopting it. Sources: *illustratorapi/illustrator/AIPathfinder.h*:107–119, 137–156, 227–252, 332–360.

`DoOutlineEffect` names a Pathfinder operation; it is not evidence of stroked-centerline expansion. `AIExpandSuite::Expand` separately documents conversion of a stroke into a closed path. Expansion of an already-beveled native result cannot recover the lost miter tip. No listed API establishes a built-in clipped-miter implementation. Sources: *illustratorapi/illustrator/AIPathfinder.h*:368–372; *illustratorapi/illustrator/AIExpand.h*:143–164; *illustratorapi/illustrator/AIPathStyle.h*:84–92, 185–194.

`AITextFrame::CreateOutline` creates new art without deleting its text source. It applies an active style but does not copy all attributes, including opacity masks; clipping text has additional exceptions. ATE frame/range accessors return reference-counted objects. None of this establishes that a frame-level stroke replacement receives character strokes or unexpanded glyph centerlines. Sources: *illustratorapi/illustrator/AITextFrame.h*:295–319, 339–347.

## Minimum native proof and acceptance gates

The first probe should prove dispatch and ownership before geometry. Register one fixed `kStrokeFilter` and an explicit native diagnostic command. The command creates its own simple, unfilled, solid-stroked straight path and attaches only the new effect. Go accepts only an open straight two-anchor path, possibly inside a narrowly validated single-child wrapper. It replaces that processing path with a filled butt-ended rectangle using the incoming stroke's color and width. This is deliberately not a miter algorithm, arbitrary selection conversion, text implementation, or full stroker port. Optional debugger diagnostics must contain only status/type/count/width, never document contents or text.

This line proof discriminates registration, callback delivery, native stroke suppression, width/color propagation, and source-versus-result ownership. It does not close the clipped-miter requirement. The next discriminating test is one acute three-anchor wedge plus a right-angle control, compared with a generic post-effect control. Measure constant flank width and the intended bisector clipping plane. A flat axial clip is not a radial distance bound; do not repeat the inherited universal right-angle-envelope claim. Geometry policy and oracle belong to the separate geometry work.

Required later host record:

1. Load only in a separately authorized session; record exact Illustrator build, plugin identity, suite versions, and binary hash. Verify startup has no document mutations and explicit command creates only its own fixture.
2. Observe Go input topology, stroke dictionary location, output geometry, and exact native stroke suppression. Verify the original source still has two anchors, remains editable, and changes rebuild the output with the same width/color.
3. Exercise unsupported roots, groups, compound paths, curves, dashes, brushes, gradients, and malformed parameters. Inject suite failures and verify rollback, returned errors, and absence of leaked art or references.
4. Add compound-path and editable-text fixtures, separating character strokes from frame Appearance strokes. Then test transforms, undo/redo, copy/paste, save/reopen, export, and missing-plugin open. No production claim follows from merely entering Go.

## Build and registration gates

The SDK sample specifies VS2022/v143, x64 or ARM64, C++17, eight-byte struct packing, an exported `PluginMain`, a DLL with *.aip* extension, and Python-generated PiPL embedded by the resource compiler. Match the host architecture and installed Windows SDK. The InDesign *.pln* project and its numeric prefix are not an Illustrator loader proof. Sources: *ReadMe.txt*:93–97; *samplecode/TwirlFilter/TwirlFilter.vcxproj*:3–44, 113–155; *samplecode/common/win/AIPluginCommon.props*:6–25; *samplecode/common/win/PluginMain.def*:1; *samplecode/TwirlFilter/Resources/Win/TwirlFilter.rc*:51–54.

Use a unique, nonlocalized effect identity, separate localized display title, explicit version, and exactly one filter type. Twirl's comment describing its identifying name as localized contradicts the header contract. Acquire suites before registration. Keep persistent state free of unload-sensitive function pointers and handle reload/shutdown explicitly. Sources: *illustratorapi/illustrator/AILiveEffect.h*:232–248, 381–400; *samplecode/TwirlFilter/Source/TwirlFilterPlugin.cpp*:224–230; *samplecode/common/source/Main.cpp*:51–139.

Ordinary filter category/title fields are Pascal strings, unlike the effect's identifying C string. The diagnostic uses a bounded `std::array` constructor with an explicit payload-length byte. Independent review caught the initial space-prefixed C strings; the new mock assertion first reproduced the invalid length, then passed after the fix. The mock checks the length before reading the exact expected payload, and compile-time assertions check the array extent. Source: *illustratorapi/illustrator/AIFilter.h*:105–122.

## Script-message proof bridge

The SDK documents `AIScriptMessage` with developer-defined input/output strings and a named-plugin dispatch example. Its ScriptMessageUI sample calls `app.sendScriptMessage(pluginName, selector, input)` directly. This supplies a supported automation route; no internal menu-command name is assumed. Sources: *illustratorapi/illustrator/AIScriptMessage.h*:39–79; *samplecode/ScriptMessageUI/js/main.jsx*:1–15.

The probe implements `status` with empty input and `create` with either `control` or `effect`. The control is an ordinary line at y = 140; the effect specimen is at y = 100. Returned JSON includes schema, plugin name, PROPOSED status, checked action result/error, effect/control fixture counts, Go-call count, successful-mutation count, last Go error, and stroke origin (0 missing, 1 transformed instance, 2 instance, 3 parameters). `status` does not mutate art, and startup never creates fixtures. Rejected protocol requests do not create art.

The adapter acquires `AIUnicodeStringSuite` for the callback, reads at most 32 ASCII input characters, and initializes the borrowed output string after destroying its previous contents. It does not cache a global Unicode suite pointer or copy SDK wrapper implementations. The host owns the message strings' outer lifetime. Sources: *illustratorapi/illustrator/AIUnicodeString.h*:69–101, 133–148, 269; *illustratorapi/illustrator/AIScriptMessage.h*:45–55.

The exact script-visible plugin name is `StrokeMasterProposedProbe`. The build verifier parses the generated PiPL `pinm` property and entry-point property, then checks that those PiPL bytes are embedded in the x64 DLL. It also records the binary hash. This verifies file identity, not Illustrator's loader interpretation. Source for generator format: *tools/pipl/pipl_gen/pipl_gen.py*:122–179.

The unexecuted *plugin/illustrator-probe/host-proof.jsx* harness creates a disposable document, compares ordinary-control and effect counter snapshots, checks the two-anchor sources, edits the effect source, and captures a structured result. It closes only its own document and restores the previously active document. Its strict fixed-schema parser needs neither `eval` nor a global JSON implementation. Successful execution would establish only observed dispatch/mutation, not native-stroke suppression, rendered fidelity, miter clipping, opacity/transparency, or full Appearance support. Counters are plugin-session-wide, so unrelated effect reevaluations can confound attribution; record the specimen state and output geometry as well. The harness has not been run in Illustrator.

Build all source, object, resource, PiPL, response, diagnostic, and binary outputs under *plugin/illustrator-probe/*. Reference installed SDK headers and tools in place. Run SDK Python tools with bytecode writes disabled and with the probe's output directory as the working directory; the inspected PiPL script writes *plugin.pipl* there. Do not copy SDK sources or headers into the repository, vendor the SDK, run sample projects in place, or create an installer. A compile/link pass establishes only compatibility with the headers/toolchain used. Loader compatibility, signing, Adobe identity/distribution requirements, and marketplace packaging remain separate unverified gates. Source: *tools/pipl/create_pipl.py*:24–51.

## Execution record

Documentation was written before optional probe implementation. Initial source inspection found no preexisting *plugin/illustrator-probe/* directory. The isolated implementation now exists there, with original source, local build files, and mock ownership tests. It implements the straight-line dispatch/ownership proof described above, not the wedge proof or full clipping algorithm.

**PROPOSED, compile-only result:** built and linked with VS2022 Community, MSVC 14.42.34433, Windows SDK 10.0.26100.0, x64, and the supplied Illustrator SDK. The final compiler configuration produced no warnings or errors. Binary inspection established PE32+ x64 DLL format, the `PluginMain` export, and a resource section. This is file inspection, not host loading or successful PiPL interpretation by Illustrator.

The mock executable passed Pascal registration-string checks, lifecycle/idempotent registration, five suite-acquisition failures, four mutation-rollback failures, nine unsupported-input/conversion cases, single-child wrapper geometry, two diagnostic attachment/cleanup cases, and protocol identity/status/input/control/effect/counter checks. No actual Adobe suite implementation was executed. Evidence is local to *plugin/illustrator-probe/build/compile.log*, *tests-compile.log*, *tests.log*, and *artifact.json*. The binary is *plugin/illustrator-probe/build/StrokeMasterProposedProbe.aip* and is ignored, not packaged for distribution.

Two local build issues were resolved without SDK edits: duplicate `PATH`/`Path` keys required normalization only in the MSBuild child's environment, and legacy SDK header encoding required an explicit Windows-1252 source charset. A mock function signature was corrected to match the declared mutable filter-name pointer. All generated build artifacts remained under the probe folder; SDK headers/tools were referenced in place, and Python bytecode writes were disabled.

Independent review identified and corrected the Pascal-string startup bug and confirmed the entry-conversion ownership contract. Remaining concerns: **high**, host dispatch and processing-art ownership are unverified, including rollback/disposal under persistent suite failure; **high**, this is not a text or miter implementation and cannot close the clipping requirement; **medium**, final review of the script bridge and registration/load/undo/persistence/export checks remain pending. No installation, Adobe process operation, restart, or SDK redistribution occurred. Native delivery remains **PROPOSED** even after the compile and mock checks.
