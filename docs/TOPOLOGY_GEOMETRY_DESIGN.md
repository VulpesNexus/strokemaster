# Topology-aware region experiment

Status: executable, bounded research prototype; not a native feature or a completed *W.jpg* validation. The original objective remains that inner spikes must never pass the surrounding outer stroke envelope. The corrected local √2 clip cannot guarantee that objective. For a closed glyph with known fill topology, the primary proposal is the positive miter buffer of the filled region itself. Executed comparisons show that it suppresses inward symmetric-stroke pieces without an externally guessed hull. Explicit envelope intersection is an optional additional constraint.

## Decision and executable scope

Use the already available Boost.Geometry 1.74 headers for a standalone C++ experiment. Union the input filled polygons before applying an outward polygon buffer. Return that filled-region buffer directly when no external envelope is supplied; intersect it with a supplied envelope when that extra constraint is intended. No polygon clipping engine is implemented here. The small distance strategy adapter disables Boost's implicit input simplification; the library still performs all buffering, intersections, unions, and differences. The previous local join kernel, Adobe plugins, scripts, and fixtures are unchanged by this work.

The implementation is [*topology_region.cpp*](../tools/topology_region.cpp), with an explicit dependency build in [*build_topology.py*](../tools/build_topology.py). Independent scalar and membership oracles are in [*test_topology_region.py*](../tests/geometry/test_topology_region.py). A reproducible test and measurement runner is [*measure_topology_region.py*](../tests/geometry/measure_topology_region.py); its generated [evidence](../tests/geometry/topology_evidence.json) records source and executable hashes, test outcomes, convergence, compiler warnings, and a small timing experiment. None of these files invokes a host API.

## Region and envelope contract

Let Fᵢ be valid, closed polygons with explicitly identified shells and holes in one Cartesian coordinate system. F = union(Fᵢ) is their filled region. Let Bₕ,ⱼ(F) be the established library's positive polygon buffer with outward distance h and declared join policy j. The primary closed-region operation is R = Bₕ,ⱼ(F), which also defines the proposed closed-region envelope E. A polygon buffer contains the original fill and expands its outside boundary; it contracts holes. It does not draw a symmetric stroke independently around every contour and retain inward miter excursions. When a separate valid E containing F is supplied, the optional constrained operation is R = Bₕ,ⱼ(F) ∩ E.

The exact set requirement is F ⊆ R ⊆ E. The executable checks a numerical approximation to those inclusions with the budgets below. It never reports exact arithmetic containment. When E is defined as the returned buffer itself, R ⊆ E is tautological and its zero residual is not independent evidence of the original artwork objective; the analytic boundary-stroke comparisons below supply the evidence. Ordinary exterior miter patches are preserved where the resolved filled boundary actually has those corners, the miter is below the declared library limit, and any extra E admits the patches. Optional `protected` polygons are explicit retention witnesses: the executable requires them inside both the candidate and E and in the result. An incompatible envelope fails instead of silently removing the supplied patch. The caller, not this prototype, establishes that a witness is an intended exterior miter.

The filled-region proposal derives its boundary from known F, not a local corner, bounding box, convex hull, font name, or the complete page. The actual fill and topology of the intended *W.jpg* artwork still need measurement, followed by a comparison with this operational policy. An external E is not a necessary prerequisite for the closed-region experiment. Open unfilled paths have no F and remain outside this proposal. The closed polygon with an open notch used below must not be confused with an open path.

## Direct filled-region versus boundary-stroke evidence

The diagnostic `compare_boundary` operation computes T = F ∪ buffer(boundary(F), h) using the same Boost join policy. Each closed boundary is represented as a linestring with its first edge repeated so every original vertex receives a join; flat terminal caps on that repeated edge add no new area. The ordinary rectangle control verifies area agreement between T and the positive filled buffer. Neither the comparison nor the positive buffer calls the repaired local kernel.

For the known closed polygon containing a downward triangular hole, the outer top is d = 0.3, h = 1.5, the hole depth is 7.5, and its apex angle is 30°. **With no external envelope**, the positive filled buffer reaches y = d + h = 1.8 and retains the ordinary outer corner (−9, 1.8). T reaches y = h/sin(15°) = 5.795555. The independent point (0, 3) lies in T but outside the positive filled buffer. The inner triangular stroke piece has crossed the thin surrounding stem; it does not exist in the positive filled-region result. No clipping intersection was used to produce this difference.

The closed polygon with a narrow top V notch likewise yields the full analytic expanded rectangle, area 146.9 and top 1.8, directly from positive filled buffering. Its resolved symmetric-boundary comparison agrees in this case: both measured tops are 1.8000000000000007, with zero reported excess area. An initial test's strict `> 1.8` assertion passed on that rounding difference and was corrected to assert agreement within tolerance. This notch is a control for topology resolution, not additional evidence of symmetric-stroke excess. The triangular-hole example above supplies the material excess. Unlike the earlier raw shifted-line counterexample, both library operations resolve the disappearing notch instead of merely reconnecting infinite offset lines.

There is a separate, explicit limit to a stronger claim. Miter buffering is not monotone under arbitrary F ⊆ O. For the triangle (0, 0), (2, 0), (2, 2) inside square O = [0, 2]², h = 1 and limit 4 produce a genuine exterior miter at x = −(1 + √2), outside B(O) = [−1, 3]². The executable reproduces that intersection. This is an admitted exterior corner, not an inward symmetric-stroke piece; it does not refute the proposed closed-glyph policy. It does refute deriving containment in every independently chosen surrounding region from F ⊆ O alone. The operational proposal preserves those genuine exterior miters while removing the offending inward contributions. Whether that matches every feature in the real artwork remains a native geometry check, not a request to redefine the user's goal.

Every request describes one authorized geometry cohort. Overlapping members of that cohort are unioned before offsetting; their internal decomposition seams cannot receive new miters. Components may merge, holes may shrink or disappear, and an island inside a hole is another polygon. No automated grouping of neighboring glyphs, formatting runs, lines, strokes of different weights, paints, or unstroked victims is performed. Those semantic boundaries must be established upstream. Combining an entire line merely because its glyphs overlap is not authorized by this geometry contract.

Traversal reversal does not change explicit shell/hole roles. This is neither an implicit even-odd decoder nor a nonzero winding resolver for arbitrary raw contours. Nested islands are separate polygons; overlapping source polygons are unioned. Self-intersecting rings, reversal cusps, open contours, two-anchor loops, repeated consecutive anchors, holes outside their shell, and nested hole roles are refused. There is no silent contour removal or `make_valid` repair. Empty output or a failed numeric/topology check returns an error without result geometry.

## Joins, units, and transforms

Coordinates and h have the same caller-defined length unit. For a centered 3 pt stroke, h = 1.5 pt; a separately specified outside stroke does not automatically use half its width. The dimensionless `limit` is relative to h. Boost's ordinary miter intersections agree with independent shifted support lines in the tested 30°, 60°, 90°, and 120° triangles. Above the limit, Boost 1.74 moves the tip toward the vertex while retaining a pointed join. That behavior is neither Adobe's conventional bevel fallback nor the repaired bisector-plane flat clip. This experiment does not claim native equivalence for those joins.

The `round` policy approximates disk dilation and supplies an independent convergence control. It deliberately does not preserve ordinary exterior miters. Reflection, rotation, uniform scale, and translation are tested. Nonuniform scale and shear require an explicit decision about the coordinate system in which distance is defined; this prototype does not claim that transforming a buffered region equals buffering a transformed region.

## Precision and convergence

Input is linear polygon geometry. Bézier parsing, adaptive flattening, analytic curve offsetting, and reconstruction are absent. Curves must not be passed through the prior fixed-subdivision flattener and labeled covered by these results. A later curve stage must declare a geometric error bound, refine until that bound is met, and check stability of counters and contacts; small positional error alone does not bound topology near a vanishing gap.

Let S = max(source bounding-box width, source bounding-box height, h). Source coordinates are translated to the source minimum and divided by S. A loose envelope does not determine source resolution. The accepted numeric range is deliberately bounded: finite coordinates and h of magnitude at most 10¹⁰⁰; positive h/S ≥ 10⁻⁷; normalized edge length ≥ 10⁻⁹; each input polygon's normalized area ≥ 10⁻¹²; input coordinate ULP/S ≤ 10⁻¹⁰; and normalized coordinates within ±10⁶. A reversing turn with absolute normalized cross-product sine below 10⁻⁷ is refused before buffering, avoiding an unbounded near-cusp miter construction. Limit is in [1, 100]. Each polygon list has at most 256 members and 20,000 vertices; each request line is limited to 4,000,000 characters after reading. These are experiment guards, not a resource-security boundary.

Default Boost rescaling is retained. The acceptance budgets are residual area ≤ 2 × 10⁻⁷ S² and residual-vertex distance ≤ 2 × 10⁻⁶ S. Difference polygons and distance checks come from the same library as construction and are diagnostic checks, not independent proof. A small residual is reported even when accepted; no zeroing of evidence occurs. Independent test checks use shifted-line formulas, exact rectangle-union area integration, translated shoelace sums, rectangle bounds, and ray crossing of output rings. They are separate from Boost and the earlier miter kernel. The finite corpus does not prove that all accepted requests satisfy a uniform error bound.

For `round`, N = `circle_points` is a multiple of four from 16 to 4096. For the tested rectangle with radius h, chord sagitta is h(1 − cos(π/N)), and the polygonal corner area is (N/2)h² sin(2π/N), compared with πh² for the disk. The tests measure area convergence and arc-midpoint sagitta at N = 16, 32, 64, 128, and 256. These formulas bound this analytic family; they do not certify all arbitrary corner subdivisions or a future Bézier pipeline. The miter polygon path has no arc-flattening parameter.

## Measured failures that shaped the prototype

The first default-library run produced two test-oracle mistakes and two library-path failures. The triangular counter remains slightly open at h = 1.5 because its inradius is 7.5 sin(15°)/(1 + sin(15°)), approximately 1.542 pt; the incorrect test expectation of zero holes was corrected analytically. An exact equality against area 10 was replaced with an explicit numerical comparison.

With the initial envelope-sized normalization and an area budget of 10⁻¹⁰, the clipping case was rejected with normalized residual 5.3112854807620359 × 10⁻⁹, and the thin stem with 2.4750172158279378 × 10⁻⁸. Turning off Boost rescaling removed the first failure but later produced a 0.0688257716625443 normalized symmetric-difference discrepancy for nearly coincident analytic hole boundaries. That mode is retained only as an optional build experiment; it is not the selected baseline or a robustness fix.

Read-only inspection found that Boost 1.74's symmetric distance strategy simplifies at h/1000. Normalization alone did not repair the thin stem. The final strategy adapter sets that simplification distance to zero, and the 10 × 0.0001 rectangle buffered by h = 0.1 now returns analytic area 2.04102 with zero reported fill loss. The selected precision budgets admit small measured overlay residuals, while the distance check separately rejects a long, narrow protrusion that an area-only budget could miss. This change is explicit tolerance policy, not an assertion that the original strict check passed.

The corpus includes an acute wedge, a near-parallel thin stem, ordinary convex corners, an open concave notch, a concave envelope, an envelope with a hole, nested islands, overlapping and duplicated sources, point contacts, hole disappearance at and around an analytic threshold, component merger around gap 2h, and a decomposition-seam negative control. Deterministic fuzz uses generator seeds 4596837 for 60 four-rectangle sets and 81745 for 24 acute triangles. The rectangle corpus also has 1,800 independent interior membership probes and repeated-request determinism checks. Invalid inputs are explicit rejection tests, not skips.

The existing 39 geometry tests passed before prototype edits. The new suite runs 29 tests with 139 successful request checks, zero failures, errors, or skips, and maximum normalized analytic area error 1.1520001885756415 × 10⁻⁷. The combined geometry discovery runs 68 tests successfully. The independently measured maximum vertex excursion beyond the clipping case's rectangle is 2.579626823262515 × 10⁻⁷ coordinate units; this is a small actual overshoot, not exact containment. The compiled default-rescale build has 12 C4244 conversion warnings in external Boost headers, plus deprecation notes; no compiler errors. These warnings are retained in the build log and evidence, not suppressed or attributed to Adobe host behavior.

No full font benchmark was run, none of the 179 previously unresolved glyph turns was discarded, and no universal font claim follows. The takeover host extraction/PDF census measurements, outline-provenance discrepancy, and MuPDF/Poppler silhouette disagreement remain separate limitations. The evidence also times 100 four-vertex rectangle requests in one process, including JSON I/O and checks; that small measurement is not a glyph or production performance claim.

The executable reads one JSON request per line and returns one JSON response per line. `source` is an array of closed `POLYGON` WKT strings, and `h` is required. Optional fields are `envelope` (another polygon array), `join`, `limit`, `circle_points`, `fill_rule` (only `explicit_roles`), `protected`, `expected` (diagnostic analytic region), `compare_boundary`, and `probes`. Success has `ok: true`, geometry as polygons of rings of coordinate pairs, library mode, `envelope_source`, areas, component/hole counts, and normalized residuals. The boundary comparison additionally returns `symmetric_geometry` and its excess area over the positive buffer. Failure has `error` and no result geometry. Process exit alone is not a request-success signal: the stream remains available after an error. The tests verify recovery on the following request.

Remaining gates are high priority: establish fill topology and cohort ownership for the intended closed glyphs, compare positive filled buffering against the actual offending geometry, validate a production-quality raw contour/curve backend, and resolve numerical and topology behavior beyond this corpus. Do not treat one PDF renderer as the sole oracle. An extra external E is needed only for an additional surrounding-region constraint; it is not required to advance the concrete closed-glyph route demonstrated here. Ordinary miter protection must be tied to real source-boundary identity upstream. The native manual benchmark gate remains pending; this task did not operate Adobe. Independent review of this new prototype has not yet been obtained, so the earlier independent local-kernel review is not presented as a review of these changes.
