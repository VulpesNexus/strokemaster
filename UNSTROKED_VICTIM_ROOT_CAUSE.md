# Unstroked victim: root cause and native replacement investigation

The currently installed native plugin is a safe-refusal control, host-validated on InDesign 21.5.1.73: all 20 census frames exported at 600 ppi produce native, reference, and mask PNGs byte-identical to plugin-absent output. It performs no additive repaint and disables **all historical A/C native corrections**. The unstroked-victim defect remains unfixed; this safety result establishes no new correction support or production readiness. The former implementation remains in baseline commit `c4596837a5e0ea10a68f7b94e2dd368032341334`.

## Concrete source cause and why widening eligibility is insufficient

Baseline references below refer to *plugin/source/IseFillRepaintAdornment.cpp* at the full baseline commit above, not the rewritten file's line numbers.

1. **P1: victim identity was confused with offender identity.** `WantsRepaint` tests the candidate victim's own Outside alignment at line 249, positive outline width at 252, and `kFillStroke` at 258. `GetCouldDraw` and `Draw` both use that predicate at 273 and 278. None of these tests asks whether a later run's stroke intersects the candidate fill. An unstroked filled victim fails even when another run visibly covers it. Conversely, an isolated thick stroked run passes despite having no offender.
2. **P1: full-run repair has no causal coverage restriction.** After installing the fill at line 317, the implementation collects every glyph outline at 344 and 351 and calls `fill()` once at 353. There is no offending-run traversal or clipping mask. Selecting a victim by a true intersection would still repaint its undamaged edges elsewhere. In ordinary source-over compositing, black at coverage 0.5 over white produces 0.5; applying the same paint again produces 0.25. Thus even perfect victim selection does not make whole-victim repaint idempotent. This is a mathematical counterexample, not a claim that Adobe's text rasterizer uses that exact numerical coverage in these fixtures.
3. **P1: native text coverage is replaced by an additional outline paint.** The old code gets outlines and issues a path fill, whereas the public native port also supports glyph-show operations. The old source has no contract equating the two rasterization paths, no original sample-coverage buffer, and no restoration of the pre-stroke destination. Installing the same rendering object reproduces requested paint parameters, not the prior destination or sampling history.
4. **P1: decoration ordering is structurally wrong for foreground repair.** The old priority is foreground + 0.90 at line 202. SDK priorities below show that this is later than strikethrough, ruby, and kenten. A fill overlay can overwrite those marks. Moving the overlay to text + 0.51 would put it before the same run's strikethrough, but later runs would still paint strokes over that repair. A separate text + 1 pass is after all text-pass decorations. There is no single adornment priority that both follows every native stroke and precedes each native decoration while leaving native run order intact.

This disproves the existing whole-run overlay and the proposed simple eligibility/priority changes under strict no-harm. It does **not** prove that every selective reconstruction algorithm is impossible. A geometric intersection mask could narrow the painted region; to qualify as a correction, it would still need to distinguish unwanted stroke coverage from legitimate fills and decorations, preserve native edge coverage, and composite within the correct transparency group. None of those mechanisms exists in the old source.

Transparent, non-Normal, overprint-sensitive, and unknown inherited appearance cannot be admitted merely because a run's fill color is known. The graphics port has opacity, blend, alpha-server, and transparency-group operations; page-item setup can establish enclosing isolation and knockout groups. Reapplying a fill afterward is not the inverse of an intervening stroke in those groups. The refusal control therefore declines every case, including opaque Normal, rather than advertising an unverified safe subset.

## Ranked replacement routes

### 1. Registered shape handler plus custom forwarding port: credible next experiment, not integrated

The public registration path is concrete. *source/public/interfaces/graphics/IDrwEvtDispatcher.h*: 73–96 defines registered handlers and ownership; *source/sdksamples/printselection/PrnSelDrawHandler.cpp*: 120–133 registers `kDrawShapeMessage`, and 185–201 suppresses unselected shapes by returning true. *source/sdksamples/basicdrwevthandler/BscDEHDrwEvtSrvc.cpp*: 110 returns `kDrawEventService`. These are SDK extensions, not replacement of Adobe's factories.

The caller-side veto is also concrete: *source/public/libs/publiclib/pageitems/basicinterfaces/CShape.cpp*: 192–197 returns before drawing when a filter or `kDrawShapeMessage` handles the event; normal drawing reaches `DrawShape` at 218. The generic `DrawFilter::ShouldDraw(IGeometry*)` in *source/public/includes/DrawFilter.h*: 43 is geometry-level filtering, not a text-stroke operator filter. Suppressing the shape alone also suppresses its native fills and page-item adornments.

A forwarding port could preserve glyph composition by forwarding the original native text calls and their arrays, offsets, matrices, font selection, clipping, paint-server operations, and searchable-text metadata. *IGraphicsPort.h*: 545–571 distinguishes fill, stroke, and clip text flags across `show`, both `xshow` overloads, and `ctshow`; 650–651 adds another searchable-text `show` form. These are concrete interception candidates. **The header does not establish that native Outside always reaches them with `kStrokeText`.** Native rendering could emit `stroke`, `StrokePath`, or filled outline geometry instead. Filtering every `stroke()` would also remove decoration and frame strokes. The port's `kTextRun` auxiliary category and text start/span fields at 67–75 and 125–153 could provide identity, but 641–648 allows ports to ignore auxiliary information; no guarantee of emission around every native run was located.

Integration requires a new viewport/context, not a pointer substitution in the event payload. *GraphicsData.h*: 67 constructs `GraphicsDataPtr` from an `IGraphicsContext`; 117–125 makes `GraphicsData` construction private; 136 exposes a getter; 256–270 caches the port and other interfaces privately. `DrawEventData.gd` is a copied pointer (*IDrwEvtHandler.h*: 102–116). Assigning a new pointer to that field cannot change the local `gd` that `CShape::ProcessDrawShape` subsequently uses. `IGraphicsContext::GetViewPort` is the public context entry (*IGraphicsContext.h*: 39–48, 79), and *ShellGraphicsContext.h*: 54–60 accepts a viewport. *IDrawMgr.h*: 103 offers `DrawAtOnce` with a context and item UID. *IShape.h*: 170–177 recommends the draw manager instead of calling shapes directly.

The plausible design is a registered, targeted handler that invokes native drawing through a custom viewport exposing a forwarding `IGraphicsPort`, under a scoped recursion guard, and then returns handled only for successful replacement. This is an **inference from composable public APIs**, not a tested integration contract. It must solve draw-manager reentrancy (`BeginShape`/`EndShape`, *IDrawMgr.h*: 195–203), same-shape recursion, transformations already installed at interception, borrowed interface lifetimes, and the other interfaces `GraphicsData` queries. Returning the target's `IAGMPortData` or capture interfaces may let rendering bypass the proxy; withholding them may change the renderer. Both possibilities need observation. *IGraphicsPort.h*: 636–639 expressly leaves port draw-manager construction to the implementation; no supplied forwarding-port implementation was found.

A streaming proxy alone cannot safely retract forwarded output after discovering an unsupported later operation. Preflight or a validated capture transaction is required before committing a replacement; falling back to native after partial drawing would double-paint. Nor is suppressing all Outside stroke bits a feature fix: it removes wanted strokes. The correction would need a validated stroke prepass/replacement region and a native pass that retains the wanted fills and decoration operations exactly once. Transparent and non-Normal cases remain refused until the new operation order is defined within native groups.

### 2. SDK capture port: real interface, opaque editing surface

*source/public/interfaces/graphics/IGfxCapturePort.h*: 49 exposes `Setup()`, 54–56 exposes AGM graphic/capture pointers, 64–85 exposes fixed-size and clip groups, and 100–106 controls fixed width and greeking. `Setup(AGMGraphic*)`, `DrawGraphic`, and `SetupWithPort` are explicitly marked internal at 51–54, 87–90, and 108–111. *GraphicsID.h*: 204–205 names capture implementations, but an implementation ID is not an operator-editing API.

*source/public/includes/BravoForwardDecl.h*: 113–115 only forward-declares `AGMGraphic`, `AGMGraphixPort`, and `AGMGraphixCapturePort`. Searches of the supplied source found no class definitions, command iterator, text-stroke editing visitor, or `IGraphicsPort` decorator implementation. The supplied capture usages in *source/open/components/buttonui/misc/FormFieldLabelDrawer.cpp*: 297–299 and *source/open/components/dynamicdocumentsui/motion/AnimationAdormentDrawer.cpp*: 148 use fixed-size graphic brackets on an existing port. They do not demonstrate interception and replay of document text.

Similarly, *IAGMPortData.h*: 43–56 stores an `AGMPort*`; its port type is intentionally undocumented at 58–66. That setter is not evidence of a supported AGM decorator ABI. Do not patch opaque AGM objects, native vtables, private `GraphicsData` fields, or globally replace Adobe port factories. The finite result is **no editable capture implementation located in this SDK**, not “Adobe has no capture system.”

### 3. Parcel/wax redraw with manually selected passes: accessible but loses the needed granularity

`IParcelShape::Draw` and `ITextParcelList::DrawParcel` retain native traversal, but their pass boundaries do not separate glyph fill from glyph stroke. `IWaxRunText::Draw` (*source/public/interfaces/text/IWaxRunText.h*: 39–52) explicitly draws text and adornments together. A custom `CWaxRunText` is an implementation of a renderer, not a registered filter around Adobe's hidden fill-only body. Temporarily editing wax is also not established as safe: *source/public/includes/TextDrawInfo.h*: 52–74 caches font and rendering state between runs. Public cache-clearing methods exist, but they do not provide an immutable native fill-only draw contract or guarantee restoration of every consumer. This route ranks below a port observation experiment.

## Source pipeline boundaries and alias capabilities

The inspected public chain is shape dispatch → native shape/parcel drawing → frame passes → wax-run text and decorations → graphics-port operators. The public caller in *CShape.cpp*: 192–218 demonstrates the first boundary; the parcel and wax headers demonstrate available calls, but their declarations are not the hidden native caller implementation. No observed native operator trace bridges the final wax-to-port boundary yet. The old overlay instead enters as an additional global adornment after native text and calls path fill; it cannot retroactively suppress the original stroke.

| Object or alias | Concrete capability | Consequence for a native replacement |
| --- | --- | --- |
| `DrawEventData.gd` | A copied `GraphicsData*`, initialized at *IDrwEvtHandler.h*: 113–116. | Reassigning this field cannot redirect the caller's local pointer. Mutating the pointed-to object would be shared state, not scoped pointer substitution. |
| Existing `GraphicsData` | Private cached graphics port, raster port, draw manager, viewport attributes, and text cache; *GraphicsData.h*: 256–270, with getters at 136, 146, 166, 187, 197, and 254. | There is no public setter that makes this existing object a proxy. A new context must yield a new `GraphicsDataPtr`; changing the current context alone is insufficient for already-cached references. |
| Original `IGraphicsPort*` | Paint and state mutation authority over the real destination: save/restore, fill/stroke, clips, transparency groups, and text-show calls. | Sharing it lets a forwarding adapter preserve actual native paint state, but forwarded marks cannot be rolled back by restoring graphics state. Do not confuse `grestore` with pixel undo. |
| Proxy `IViewPort` and `QueryInterface` aliases | `IViewPort` is a viewport-boss handle (*IViewPort.h*: 30–38); a native consumer can query additional interfaces from related boss objects. | Forwarding `IGraphicsPort` alone is not evidence that every consumer crosses it. An alias to the original raster/capture/AGM interface may bypass interception; a missing alias may cause a different rendering path. No blanket “delegate every other IID” rule is established as safe. |
| `IAGMPortData`, `IGfxCapturePort` | Can return opaque native port/capture pointers; evidence and internal-only boundaries are cited above. | These are powerful aliases without a public editing contract in the inspected SDK. An interface-query trace is needed before granting them to a proxy. No vtable or opaque-object patch is proposed. |
| Borrowed wax runs and rendering data | Iteration and geometry/paint inspection, with borrowed lifetime and native caches. | Snapshot plain selection/geometry data before advancing; do not cache dangling run pointers or mutate wax to fake a native fill-only pass. |

The refusal control closes every paint path before any of these capabilities is acquired. Its pure shims prove that the current entry points compile and run without port/traversal access; they do not prove how a future proxy will interact with native aliases. These capability restrictions apply to the source and binary hashes recorded below.

## Next discriminating implementation and host tests

1. **Transparent-forwarding prototype first.** In a separate diagnostic native build, register the targeted draw handler and construct the custom viewport/context. Initially change no operators. The pass-through output must match no-plugin native output exactly for the 20 census cases, preserving searchable PDF text, page-item decorations, and document state. Failure here rejects the integration route before developing correction geometry.
2. **Trace operation identity without content.** Count each text-show overload, stroke flags, path stroke/fill calls, auxiliary run brackets, transparency groups, and proxy-bypass interface queries for one throwaway Outside run and its None/Center controls. Use numeric counters and opaque run indices, not user text or color values. This determines whether text-stroke-only filtering is possible at this boundary. No `kStrokeText` call does not mean no stroke; correlate path operations before drawing conclusions.
3. **Suppress one known stroke in the diagnostic document only.** Preserve fill and clip flags and metadata, maintain path consumption and save/restore behavior, and refuse unmatched auxiliary identity. The expected experiment result is missing stroke with unchanged native fill/decorations, not completed overlap correction. Test both screen and export; one does not establish the other.
4. **Only then implement selective replacement.** Identify the exact unwanted contribution, validate stroke geometry and native state before output, and preserve the native decoration schedule. Thin and thick nonoverlap controls must be unchanged outside any proven correction region. Test strikethrough separately from underline, including later-run overlap. Do not substitute “all decorations on top” as the contract.

This route is sharply bounded by two missing observations: whether an unmodified native redraw can traverse the custom port without changing output, and whether native Outside stroke contribution is distinguishable from wanted text/decorations there. The SDK supports attempting that experiment; it does not yet support claiming the resulting feature.

### Ranked findings and cheapest discriminating checks

1. **P2 — census collection can report success after failed output or setup.** *probe-victim-census.jsx*: 101 calls `lib.writeText`, then sets `done` at 102; its success predicate at 104–105 checks only selected log spellings. The helper in *ise-lib.jsx*: 273–280 ignores false return values from file open/write/close. A failed manifest write can therefore leave `passed: true`. Separately, the requested style at probe line 27 uses *ise-lib.jsx*: 209–212, which catches assignment failures and logs lowercase `failed:`; that spelling is not rejected by the probe's predicate. Both paths were reproduced with the actual library in a pure VM: false file-operation returns do not throw, and an injected rejection of `strokeWeight = 12` logs a failure while the probe's success predicate accepts the log. Cheapest correction/tests: fail on required write results and verify artifact existence/nonzero size; assert the fixture's required style and each case's distinguishing properties before native export. Do not reinterpret the already-generated image evidence as failed merely because these latent paths exist.
2. **P2 — library-load exceptions bypass global restoration in both probes.** *probe-victim-census.jsx*: 10–12 changes globals before the protected block begins at 22; *probe-census-persistence.jsx*: 10–11 does the same before line 25. Also, assigning `undefined` in each `finally` does not restore absence of a formerly absent property. Cheapest correction/test: include evaluation inside the protected block and snapshot property presence as well as its value. The recorded successful runs are not invalidated by this failure-path defect.
3. **P2 — toggle COM release is success-only.** *toggle-id-prototype.ps1*: 28–44 acquires a COM reference, captures documents, writes the restart record, and requests quit; release occurs only at 45. Any exception after acquisition bypasses release and GC. This matters particularly in the observed environment where host exit is sensitive to client lifetime. Cheapest test: inject exceptions at the capture and quit calls and assert release in `finally`, without closing or launching a real host. The script's existing check at 50 correctly refuses to move the binary while InDesign remains running. A retained COM reference is a plausible cause of delayed exit, not a proven explanation for the observed blank-title process.
4. **P2 — installation is a partial transaction, and its status flags can underreport completed mutations.** *install-native-diagnostics.ps1*: 19–27 copies the Illustrator plugin and then moves the InDesign binary, with no rollback in the catch at 29–31. The flags are updated only after destination hash verification. A copy/move that completes followed by a verification error can therefore leave changed files while the corresponding flag remains false. A later failure can also leave Illustrator installed while InDesign remains enabled. The final log write at 33 can itself mask the original error; its directory is assumed to exist. Cheapest tests: mock file operations and inject failure after each copy/move and during logging; assert either verified rollback or a precise partial-state record. Preserve the holding binary as the authoritative backup, and never infer filesystem state from `success: false` alone. This is failure-path analysis; *native-install.json* reports a successful observed transaction.
5. **P2 — broad preservation field names exceed what the signatures measure.** *probe-victim-census.jsx*: 15–20 compares characters, horizontal offsets, and baselines; line 102 calls that `glyphPositionsUnchanged`. It does not inspect glyph IDs, matrices, substitutions, or full transforms. *probe-census-persistence.jsx*: 13–23 additionally samples stroke/fill names, stroke weight/tint, and join, but excludes font, point size, fill tint, opacity, decorations, stroke alignment, and frame transforms. Its field at 45 should be read as preservation of those sampled fields. A pure check of the actual census function accepts altered point size, fill tint, strikethrough, frame rotation, and opacity because those fields are absent. Cheapest test: mutate each omitted field in a mock signature test and either expand the signature or narrow the result label. Exact rendered equality from the real persistence run is separate, stronger evidence for its specific fixture; it still is not a universal state-preservation guarantee.

### Oracle, negative controls, and preservation boundaries

The reference construction is appropriate for the present opaque, simple-run hypothesis: *probe-victim-census.jsx*: 77–85 duplicates each frame, removes fill/decorations from the lower copy, uses a centered stroke of twice the stored width with the original stroke color, and sets the upper copy to None plus zero weight. It preserves None-versus-positive-weight negative controls by copying the actual color rather than inferring stroke presence solely from width. The baseline and no-plugin reference equality independently supports the current fixture. However, the reference shares the native compositor and inherited text appearance; it is independent of the plugin's foreground algorithm, not an independent implementation of every native text semantic. Nonzero partial opacity, non-Normal blending, overlapping differently colored frames, arbitrary effects, and other stroke alignments are not certified by these 20 cases. Duplicating appearance across two frames would require a separate oracle in those cases.

The mask at lines 94–100 removes stroke/decorations and paints Paper text on a Black background. It intentionally retains VC09's zero content opacity, producing an empty mask. Consequently VC09 must be judged by full-frame/region differences and expected invisibility, never by zero core differences. For future partial-opacity cases, a threshold of 254 would likewise not supply an opaque glyph core without a separate geometry mask. *tools/compare_renders.py*: 31 defines a difference threshold of eight: `changed_px = 0` ordinarily means no differences above eight, not pixel identity. The any-nonzero comparison for VC03 and VC09 also returns zero for both. The comparator's `edge_changed_px` means every changed pixel outside the eroded mask, including decorations and background, not just glyph edges.

The seven independently checked regions use the comparator's 12-point padding, and the reference/mask manifests match between runs. This regional check does not certify crop isolation for every rotated or future larger-stroke case. This does not test an unrelated preexisting document's rendered output: the live-document log samples names and saved/modified booleans, not document IDs, selected objects, active window, zoom, or rendered content. Those are limits of the preservation evidence, not proof that unrelated documents were changed.

Ownership is substantially guarded. The census creates and tracks a fresh hidden document at line 24; the persistence probe rejects an exact already-open source at lines 7–8 and calls `lib.track(app.open(...))` at 27 before mutation. Although that lexical path check is case-sensitive and does not canonicalize junction aliases, *ise-lib.jsx*: 99–100 and 136–140 independently rejects a returned preexisting document by object/ID identity. Therefore an alias returning the same open document should be refused before the probe's explicit close/save calls; the lexical weakness alone is not a confirmed unrelated-document-close bug. Input/output target existence checks prevent ordinary overwrites, but are not atomic filesystem reservations.

The persistence script opens the supplied source itself, not a separate disk copy, despite the wording at line 1. Its current successful sequence only recomposes/exports that source and closes it with `SaveOptions.NO` at 37; the save at 40 targets a new reopened artifact. No destructive source save was found. If future steps mutate/save the first document, ownership of an opened handle must not be mistaken for permission to overwrite the input file.

The toggle requires the expected source hash and absent destination at 13–14, refuses multiple/unexpected host processes at 27, checks saved/modified state again in the quit script at 42, and refuses binary movement if a host survives at 50. It never force-terminates. Its restart record is written at 39 **before** quit; the no-host branch at 17–24 validates action/hash, not a recorded completed shutdown.
