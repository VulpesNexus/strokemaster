# StrokeMaster research revival, 2026-09-25

This pass resumed StrokeMaster from its repository, history, tests, and host evidence, and pushed the native routes in both primary hosts. Every claim below carries one status: **PROVEN** (demonstrated here by code, host experiment, or reproducible fixture), **ESTABLISHED** (documented by an authoritative SDK or Adobe source), **DERIVED** (follows from proven or established evidence, with the reasoning given), **HYPOTHESIS**, **REJECTED**, or **BLOCKED** (with the exact blocker).

Hosts measured: Illustrator 30.7.0, build 114R, and InDesign 21.5.1.73, on Windows x64. SDKs: Illustrator 2026 and InDesign 2026, MSVC 14.42.34433, Windows SDK 10.0.26100.0.

## Independent review

The new plugin and geometry code had one independent read (read-only, against the SDK headers) before this report closed. It found three P1 risks, none host-confirmed: route W depended on when InDesign asks `GetCouldDraw` and which passes Start/End reach; and stroke-behind did not refuse a path or compound root. P2 findings: stroke-behind's gates missed art-style content (multiple paints, per-paint blending, opacity masks); route W could write a stale stroke color after a recomposition; the flattening bound was √2 × the tolerance at cusps; ring roles assumed winding; and the appearance command did not check that its stroke sits beneath the contents. All were fixed in `77b08e9`, `f2f6079`, and `06315a2`, with regression tests, and region-prep-11 reproduced every Illustrator host result unchanged ([record](tests/audit/results/illustrator-region-prep11-regression.json)).

## Route W host test

The owner installed route W (`f31dd2c9…`) from an elevated PowerShell with *tools/install-indesign-plugin.ps1*, which backed up the refusal build and verified every hash; InDesign 21.5.1.73 loaded the module from *Plug-Ins*. The unchanged 20-case victim census then ran against it in an owned document, and the saved fixture was re-exported to PDF ([record](tests/audit/results/indesign-routew-victim-census.json), regenerated by *tools/record_routew_census.py*).

- **PNG, fill core:** 0 changed pixels in every one of the 20 frames against the split reference. Without the plugin, 13 frames lost 2,877–4,677 core pixels each (3,762 in each of the five victim cases; the earlier record's 3,759 used that run's mask).
- **PDF:** 42 live *HH* lines in the embedded MinionPro font. Every frame paints its strokes before its fills; the only strokes after a fill are VC15's two 5 pt strikethrough bars, which InDesign always draws on top. Stroke widths are exactly route W's doubled weights (24, 6, and 0.2 pt). The MuPDF render has no fill-core pixel more than 64 levels from the reference (maximum 46, from the CMYK black conversion).
- **Edits after a draw:** the census restyles every frame after the route W export, for its reference and mask renders. Both match the no-plugin run pixel for pixel outside VC18, so no muted or restored paint went stale.
- **Not bit for bit:** route W's stroke edges differ from InDesign's own stroke in a one-pixel ring (at most 108 of 255 per channel, net coverage within a sub-pixel), so the benign controls VC11–VC13, which matched their reference exactly without the plugin, now differ at the edge by 2,493–5,398 pixels. Route W strokes the font's outlines through the graphics port; that InDesign's text stroker flattens or rasterizes the same outlines slightly differently is a HYPOTHESIS.
- **Oracle limits found:** VC14's underline sits beneath the text stroke natively, with or without the plugin, while the split reference paints it on top, so the reference is not an oracle for underlines. VC18's rotated frame moved 11.5 pt between the no-plugin session and this one, in the reference as well as the native render, so VC18 compares only within one run.
- **Stability:** no application error or hang in the event log; InDesign stayed responsive throughout.

**Fixture-suite survey.** Every saved document under *tests/indesign-stroke* (12 documents, suites A, B, C, D, N, S, T, and the corpus) was re-exported with route W installed and measured against the committed no-plugin exports and the strokes-first oracle PDFs, all rendered by MuPDF ([survey record](tests/audit/results/indesign-routew-fixture-survey.json), regenerated by *tools/record_routew_survey.py*; each suite's manifest matches its no-plugin export frame for frame).

Against the oracle PDFs at 300 dpi, suite C has 27 of 50 variants off by more than 128 levels natively and 1 with route W (C03, 4 edge pixels on a magenta stroke); suite A's five defect frames all match.
- **Across frames it does not reach.** A06–A08 are two overlapping frames, where the front frame's stroke covers the back frame's fill. Route W works within one frame's passes, so they stay as native (2,126 → 2,271 and 1,536 → 1,413 covered pixels, the edge ring); the withdrawn repaint plugin had the same limit.

- **PDF text appears once.** InDesign writes each stroked line twice, a stroke-mode copy and a fill-mode copy, so extraction returns the text twice (998 characters for the corpus's 500); route W's PDFs carry only the fill copy.
**Print drawing (EPS and PostScript).** EPS export and printing to a PostScript file use InDesign's print drawing, not PDF export. Rendered by Ghostscript 9.23 ([print record](tests/audit/results/indesign-routew-print-paths.json), regenerated by *tools/record_routew_print.py*):

## C. Illustrator native status

**Load: PROVEN.** Already proven before this pass, and repeated in ten plugin-loaded processes today with no faults.

**Rendering intervention: PROVEN, for two bounded fixtures.** The usable intervention point is the **live effect** (`AILiveEffectSuite`, post-effect) on the source object's art style, not a stroke-generator replacement. Illustrator builds the styled art, hands it to Go, and draws and exports whatever Go leaves. The source stays editable, save/reopen keeps the effect and its cached result, and undo works.

- **Q20 resolved.** Four plugin-side causes, each measured and fixed: the wrapper gate counted None paint fields (fix: `ContainsPaint`); the output stage assumed one processing child (fix: locate the contents by group-contents position and require every other child to be demonstrably unpainted); readback was compared bit for bit (fix: 1e-4 pt tolerance, deltas reported); and refusals returned an error that raised a modal alert (fix: pass the processing copy through, report only a failed rollback).
- **Region correction (topology core, marked analytic fixture).** Published through both the plugin's own attachment and the host's `PageItem.applyEffect`. PDF: one filled vector region, the hole kept, minimum x −0.3000; the native control's hole miter escapes the 0.2 pt wall to −0.4708. Both PDFs pass *tools/measure_region_pdf.py*.
- **Stroke-behind (live text, paint order).** Two lines of *HH* on 34 pt leading, 8 pt mixed per-character strokes, and an unstroked victim glyph: fill-core damage 55,568 of 72,080 pixels natively, 0 corrected (MuPDF, 600 dpi). Against the outlined pass-through control, which shares the export route, ink coverage and every pixel away from the fills are identical. It republishes after live edits and undo, and after a fresh-process reopen.

- **Native Appearance (uniform strokes).** Region-prep-10's bridge writes one object-level stroke beneath a text frame's characters, a plain style with no effect. On the uniform-stroke fixture it removes all damage, keeps PDF text and fonts, and needs no plugin to render, export, or follow edits (claims 24 and 25).

**Constraints, all measured:** under any effect the PDF carries text as outlines (claim 8); without the plugin, edited text under an effect renders stale (claim 15), which the Appearance route avoids; effect order relative to other Appearance entries, transforms, gradients, and transparency are refused or untested.

## D. InDesign native status

**Can InDesign 21.5.1.73 load native compiled plugins? PROVEN (earlier), confirmed installed today.** SDK 2026, MSVC 14.42, a *.pln* in *Plug-Ins\InDesignStrokeEngine* with its *(InDesignStrokeEngine Resources)* folder; the installed refusal build `15b802eb…` loads and changes no pixel.

**Can such a plugin influence the relevant output? PROVEN on the 20-case fixture.** InDesign's own text drawing order is the fault (claim 9), and the SDK's adornment passes are frame-wide (claim 10). Route W (*plugin/source/IseStrokeBehindAdornment.cpp*, opt-in with *build-plugin.ps1 -RouteW*) strokes each Outside-stroked run, in a pass of its own after the frame's Background pass and before Text, with the run's own stroke rendering object at twice the weight, sets the run's stroke paint to [None] in the wax until the Foreground pass, and restores it there. After the independent review it no longer relies on when the host asks `GetCouldDraw` or which passes Start/End reach: both adornments decide in `Draw`, and a run left muted by a missed Foreground visit is restored at the next draw's first visit, never overwriting a stroke the run has since been given. The document's attributes are never changed, so without the plugin the same document draws natively and InDesign's own stroke controls remain the user interface. The fills remain native text, so PDF keeps searchable text and fonts, unlike Illustrator's effect route.

**Can it correct strokes while preserving live text? PROVEN on the 20-case fixture (claim 18).** Route W (27,136 bytes, `f31dd2c9…`, 22 pure ledger scenarios) was installed by the owner and measured in PNG and PDF export (see *Route W host test* above). The Text pass honors the muted paint on both output paths measured. Since measured: the saved fixture suites (claim 33), EPS and print output (claim 35), and screen drawing followed by exports and a saved copy (claim 36; the screen itself checked by eye). The fallback, should an output path ignore the muted paint, remains **route A**: a plugin character attribute (the SDK's *basictextadornment* sample shows attribute, adornment, scripting, and root-style responders) holding the stroke, with the native stroke set to None.

**Scripts as a front end.** The existing split, resync, and outline scripts stay valid document-level alternatives. With route W they are not needed for correction, because route W reads InDesign's own stroke attributes; they remain migration and diagnostic tools.

## F. Geometry findings

- **The unstroked victim is paint order, not geometry (claim 19).** Moving every stroke beneath every fill removed all fill-core damage without any Boolean operation, while leaving coverage identical.
- **Topology is needed where a stroke escapes every fill.** The region fixture's hole miter pierces the outer wall and lands outside the shape, where no fill order can hide it; the linked topology core removes it and keeps the ordinary outer miters (PDF measurement, claim 11).
- **Clamped rather than rounded joins.** The published region keeps miter joins inside the limit and removes only the inward excursion; the measurer's `ordinary_outer_corner_preserved` check passes.
- **Formatting runs.** The stroke-behind transform keeps each glyph's own stroke paint and relative order, so mixed per-character strokes are handled without merging formatting (fixture: three stroke states across two lines).
- **Curves and real glyphs.** *tools/curve_region.py* flattens cubic contours (both control points within the tolerance of the chord) and assigns ring roles by containment depth, refusing crossing or touching contours. On analytic curves the core's result stays within the band the tolerance allows, and the miter policy carries over: a 30° lens tip keeps its full miter, a 20° tip is clamped flat at 4h (claim 27). On real glyphs, five system fonts pass at 97–99% per static font with no lost fill (claims 28 and 29).
- **Still open:** fill-rule resolution for touching or overlapping contours (a reviewed Boolean pre-pass before the core), and applying the core to glyph outlines inside the Illustrator stroke-behind route.

## H. Architecture decision

The evidence supports **a shared StrokeMaster core with host-specific native adapters**, and nothing larger:

- No shared Adobe component can be hooked (claim 20), and the two hosts expose unrelated extension points: Illustrator a post-effect over styled art, InDesign frame-wide text adornment passes.
- What is shared is decided above both hosts: the paint-order rule (all strokes of a text object beneath all its fills), the topology rule for escaping joins (the reviewed core), and the measurement contracts.
- Illustrator adapter, two tiers. **Uniform strokes:** author a native object-level Appearance stroke beneath the characters (and clear the character stroke); the result is ordinary document data, keeps PDF text, and needs no plugin at render time (claims 24 and 25). **Mixed per-character strokes:** the live effect declaring path and compound input, applying stroke-behind to glyph outlines and, where a stroke escapes a fill, the topology core; its costs are outlined text in PDF and stale drawing when the plugin is missing.
- InDesign adapter: **route W**, host-proven on the 20-case census and the saved fixture suites (claims 18 and 33); route A stays the fallback for any output path found to ignore the muted paint. Overlap between separate frames (claim 34) is document stacking and stays with the document-level tools.
